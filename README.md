# 🖤 Bless Die CRM

Личная CRM в Telegram-боте для реселлера одежды **Bless Die**. Быстрый, минималистичный
инструмент для учёта заказов с телефона — без лишних действий и экранов.

## Возможности

- ➕ Пошаговое создание заказа (фото, название, размер, закупка, продажа, покупатель, комментарий)
- 📦 Список всех заказов с пагинацией (по 10), фильтрами (все / в работе / проданные) и сортировкой
  (новые / старые / самые дорогие / самая большая прибыль)
- 🔍 Поиск по ID, названию, размеру, Instagram или имени покупателя
- 📊 Статистика: количество заказов, суммы закупок/продаж, общая и средняя прибыль
- ✏️ Редактирование любого поля заказа отдельно
- ✅ Закрытие / ♻️ повторное открытие заказа с автоматической фиксацией даты продажи
- 📋 Дублирование заказа (для одинаковой модели в разных размерах)
- 🗑 Удаление с подтверждением
- 🕐 Быстрый доступ к последнему заказу
- Защита от случайных двойных нажатий
- Доступ только для владельца (до 3 Telegram ID)
- Прибыль считается автоматически — вручную вводить не нужно
- Фото хранятся через Telegram `file_id`, без скачивания и локального хранения

## Стек

Python 3.12 · aiogram 3 · PostgreSQL · SQLAlchemy 2 (async) · Alembic · Docker / Docker Compose

## Архитектура

```
app/
  main.py            точка входа, Dispatcher, middlewares
  config.py           настройки из .env (pydantic-settings)
  database/            engine, async session factory, Base
  models/               ORM-модель Order (профит считается автоматически через event listener)
  repositories/       Repository Pattern — весь доступ к БД
  services/              Service Layer — бизнес-логика поверх репозитория
  middlewares/     проверка админа, сессия БД, антидабл-клик
  filters/                дополнительный фильтр IsAdmin
  states/                FSM-состояния (создание/редактирование/поиск)
  keyboards/          Inline-клавиатуры и безопасные CallbackData
  handlers/           обработчики по разделам (старт, заказ, список, поиск и т.д.)
  utils/                  форматирование текста, валидация ввода, тексты интерфейса
migrations/          Alembic (env.py настроен на async-движок и .env)
```

## Запуск через Docker Compose (рекомендуется)

1. Скопируйте `.env.example` в `.env` и заполните:

   ```
   BOT_TOKEN=токен_от_BotFather
   ADMIN_ID_1=ваш_telegram_id
   ```

   `DATABASE_URL` для локального compose-запуска можно оставить пустым — контейнер `bot`
   подключается к контейнеру `db` автоматически.

2. Запустите:

   ```
   docker compose up -d
   ```

   При старте контейнер `bot` сам применяет миграции (`alembic upgrade head`) и запускает бота.
   Больше никаких ручных действий не требуется.

## Деплой на Railway

1. Создайте новый проект на Railway из этого репозитория.
2. Добавьте плагин **PostgreSQL** — Railway создаст переменную `DATABASE_URL` автоматически
   (формат `postgresql://...`). Переименуйте/добавьте её как `DATABASE_URL` в переменные окружения
   сервиса бота в формате `postgresql+asyncpg://...` (замените схему `postgresql://` на
   `postgresql+asyncpg://`).
3. Добавьте переменные `BOT_TOKEN`, `ADMIN_ID_1` (и при необходимости `ADMIN_ID_2`, `ADMIN_ID_3`).
4. Railway соберёт образ по `Dockerfile`. `entrypoint.sh` применит миграции и запустит бота.

## Локальный запуск без Docker (для разработки)

```
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # заполните переменные
alembic upgrade head
python -m app.main
```

## Переменные окружения

| Переменная    | Обязательна | Описание                                            |
|---------------|-------------|------------------------------------------------------|
| `BOT_TOKEN`   | да          | Токен бота от @BotFather                              |
| `DATABASE_URL`| да          | Строка подключения к PostgreSQL (`postgresql+asyncpg://...`) |
| `ADMIN_ID_1`  | да          | Telegram ID владельца бота                            |
| `ADMIN_ID_2`  | нет         | Второй администратор (опционально)                    |
| `ADMIN_ID_3`  | нет         | Третий администратор (опционально)                    |

Любой пользователь, чей ID не указан в `ADMIN_ID_1/2/3`, получает сообщение
«🚫 У вас нет доступа» и не может пользоваться ботом.

## Заметки по данным

- Прибыль (`profit`) вычисляется автоматически на уровне модели (SQLAlchemy event listener)
  при каждом создании/изменении заказа — вручную это поле никогда не задаётся.
- Фото хранится только как `file_id` Telegram — файлы не скачиваются и не хранятся на диске.
- Все callback-данные собираются через `aiogram.filters.callback_data.CallbackData` —
  структурированы, типизированы и укладываются в лимит Telegram в 64 байта.
